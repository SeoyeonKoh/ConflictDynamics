# 사후 에이전트 인터뷰 설계

2026-11-03 · 대상: `src/conflict_sim/`(서버·엔진), `viz/`(뷰어)
선행 작업: `2026-11-03-viz-main-menu-design.md` (conflict-server, 뷰어 페이지, 대화 탭)

## 1. 의도

run을 보다가 "왜 그때 쉬었지?", "왜 돌려보냈지?" 같은 궁금증이 생기면, 그 순간에 그 에이전트에게 직접 묻는다. 답은 휴식·갈등의 *이유*를 알려 주는 질적 자료로 실험(반복 실험 프로젝트)에 쓰인다. 그래서 답은 사후 해설이 아니라, 그 시점의 그 사람이 가진 것만으로 나와야 한다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 뷰어(리플레이·라이브)에서 아무 시점에나 에이전트 한 명을 골라 채팅으로 질문한다.
- 에이전트는 **그 시점까지의 기억만으로** 답한다(사용자 결정). 그 뒤의 일은 모른다.
- 인터뷰 대화는 저장되고(사용자 결정), 같은 화면에서 다시 열어 볼 수 있다.

**비목표**
- 인터뷰가 run을 바꾸는 것: 에이전트 기억·관계·기록에 아무것도 더하지 않는다.
- 여러 에이전트에게 한꺼번에 묻기, 에이전트끼리 대화시키기.
- 인터뷰 결과의 자동 분석·요약.
- 라이브 run의 엔진 프로세스 안에서 묻기(엔진을 멈추거나 끼어들지 않는다).

**반목표**
- 그 시점 뒤의 기억이 답에 섞인다.
- 인터뷰가 run 폴더의 기존 파일(events, frames, memory, tape)을 바꾼다.
- API 키가 브라우저로 간다.

## 3. 제약

- 새 Python 의존성 없음. conflict-server(`server.py`)에 API를 더한다. 같은 보안 규칙(로컬 Host/Origin, JSON 본문)을 따른다.
- LLM은 환경 설정의 provider(OpenAI/Demo)와 모델을 쓴다. Demo면 규칙 응답.
- 화면 문구는 한/영 사전(`i18n.ts`), 테마 토큰, Pretendard를 따른다.
- 커밋에 AI attribution 없음.

## 4. 결정된 사항 (사용자 결정)

- 아무 시점·아무 에이전트 한 명, 채팅 형태.
- 그 시점까지의 기억만.
- 대화 저장.
- 화면은 목업 `docs/superpowers/specs/2026-11-03-agent-interview/interview.html` 그대로:
  - 지도에서 에이전트를 누르면 나오는 카드(기존 inspect 패널)에 "💬 인터뷰" 버튼.
  - 오른쪽 채팅 패널: 이름, 역할, 그 시점의 스트레스·기분, "N일차 HH:MM까지의 기억으로 답해요" 표시, 예전 인터뷰 고르기(이 에이전트, 이 run).
  - 대화: 내 질문은 오른쪽 파란 말풍선, 답은 왼쪽 회색 말풍선. 맨 위 안내 "인터뷰는 run에 영향을 주지 않아요 · run 폴더에 저장돼요".
  - 입력칸 + 보내기, 그 위에 "질문 1번에 LLM 1회 호출 · <provider/모델>".

## 5. 구조

### 5.1 그 시점의 에이전트 다시 만들기 (`src/conflict_sim/interview.py`)

엔진을 재생하지 않고 run 폴더 파일에서 만든다. 모든 run(기록 테이프가 없는 예전 run 포함)에서 된다.

| 재료 | 출처 | 시점 t 기준 |
|---|---|---|
| 페르소나·이름·역할 | `resolved_config.json` agents | 그대로 |
| 기억 | `memory.sqlite` records(+embedding) | `created_tick <= t` |
| 스트레스·기분·관계·최근 회고 | `inspect.jsonl` | 그 에이전트의 `tick <= t` 마지막 줄 |
| 그 시점에 하던 일·있던 곳 | `frames.jsonl` | `tick <= t` 마지막 frame의 그 에이전트 항목 |
| 오늘 계획 | `events.jsonl`의 `action` `kind: plan` | `tick <= t` 마지막 것 |

- 질문마다 관련 기억을 고른다: 엔진의 `MemoryStore.retrieve`(`agent/memory.py`)를 그대로 쓴다. `storage.read_memory()`의 기록을 `created_tick <= t`로 걸러 MemoryStore를 만든다.
  - **질문 임베딩은 run 자신의 임베딩 모델로 (설계자 결정)**: 저장된 벡터는 run이 쓴 모델의 것이다(OpenAI 1536차원 / Demo 32차원). 대화 모델은 서버 설정을 따르지만, 질문 임베딩은 `resolved_config.json`의 backend·`model_embed`로 한다. OpenAI run인데 키가 없으면 관련도 없이(최근성·중요도만) 고르고 화면에 그렇게 알린다.
  - **최근성 (설계자 결정)**: 엔진은 `last_access`로 최근성을 계산하고 검색할 때마다 갱신한다. 파일에는 시점별 `last_access`가 없으므로 `memory.sqlite`의 `retrievals` 표(에이전트, tick, ids)로 t까지의 마지막 접근을 다시 만든다. 없으면 `created_tick`.
  - **"t까지"는 t 포함 (설계자 결정)**: tick t 안에 생긴 기억과 tick t 끝의 inspect/frame까지. 뷰어가 tick t에서 보여 주는 상태와 같다.
  - 화면의 호출 표시는 "질문 1번에 LLM 1회 + 임베딩 1회"(Demo run이면 임베딩은 무료 해시).
- 프롬프트: 엔진의 사람 말투 프롬프트 재료(`agent/human.py`의 `persona_card` 등)로 "너는 <이름>이다. 지금은 <N일차 HH:MM>이다. 아래는 지금까지 네가 기억하는 것이다…"를 만들고, 인터뷰 대화(앞선 질문과 답)를 붙인다. 지시: 그 시점의 자기 입장에서 1인칭으로, 모르는 것은 모른다고 답한다. 출력은 자연어 한 덩어리(JSON 아님).
- 언어: 시나리오 `language`(예: Korean)를 따른다.

### 5.2 저장

- run 폴더에 `interviews/<id>.json` 하나씩: `{id, agent, tick, provider, model, started, turns: [{q, a, at, retrieved: [memory ids], tokens}]}`.
- 저장은 서버가 한다. run 폴더의 다른 파일은 건드리지 않는다.
- 라이브 run도 같은 폴더에 저장(엔진 프로세스와 파일이 겹치지 않음).
- **run이 나중에 다시 만들어질 때 (설계자 결정)**: 이어서 실행(체크포인트 잘라내기)이나 기록 재생은 기억 DB·journal을 다시 쓰고, 기억 id(`<agent>:<n>`)가 다른 내용을 가리킬 수 있다.
  - 그래서 각 답에는 id와 함께 **고른 기억의 원문**을 저장해 인터뷰가 스스로 완결되게 한다.
  - 인터뷰에 만들 때의 run 세그먼트 수(`manifest.json`의 `token_usage_segments` 길이)를 적고, 지금과 다르면 화면에 "이 인터뷰 뒤로 run이 다시 만들어졌어요" 표시. 이어서 물을 때는 지금 파일 기준.
  - run이 기록 재생 중(서버가 아는 상태 `replaying`)이거나 `.before-replay`가 있으면 새 질문을 409로 거절한다(반쯤 만든 파일을 읽지 않게).
- 설정 검증에 실패하는 아주 옛 run(예: `runs/c16-demo-nob`)은 인터뷰 버튼을 끄고 이유를 보여 준다.

### 5.3 API (conflict-server)

| API | 하는 일 |
|---|---|
| `GET /api/runs/<run>/interviews?agent=<id>` | 그 run의 인터뷰 목록(에이전트로 거르기): id, agent, tick, 질문 수, 시작 시각 |
| `GET /api/runs/<run>/interviews/<id>` | 인터뷰 하나 전체 |
| `POST /api/runs/<run>/interviews` | 새 인터뷰: `{agent, tick}` → 빈 인터뷰와 그 시점 요약(이름, 역할, 스트레스·기분) |
| `POST /api/runs/<run>/interviews/<id>/ask` | `{question}` → 답 한 개, 저장 후 돌려줌 |

- provider·모델은 서버 설정에서. OpenAI는 키가 `.env`에 있어야 하고 없으면 409로 이유를 알린다.
- 인터뷰 질문은 비용이 작아서 run 시작처럼 확인 창을 두지 않는다(설계자 결정). 화면에 호출 수와 모델을 늘 보여 준다.

### 5.4 화면 (viz)

- 뷰어 inspect 패널(`hud.ts`, `#side` 안의 sheet)에 "💬 인터뷰" 버튼. 누르면 **같은 `#side` 안에서 inspect 자리를 채팅 패널이 덮는다**(설계자 결정, 닫으면 inspect로 돌아감). 목업의 지도 위 카드는 기존 inspect 패널이 그 역할을 한다.
- 기준 시점은 `world.frame.tick`(슬라이더 위치가 아니라 지금 보이는 frame의 tick). run 경로는 리플레이면 `?replay=` 값, 라이브면 `/api/live`에서 찾은 run. `?ws=`로만 연 뷰어는 run 경로가 없으므로 버튼을 끈다.
- Demo 대화 모델은 엔진 JSON용 규칙 응답을 쓸 수 없어 인터뷰 전용 Demo 답을 둔다(고른 기억 몇 개를 인용).
- 시점을 바꾸면(슬라이더 이동) 열린 인터뷰는 그대로 원래 시점 기준이다. 새 시점으로 물으려면 새 인터뷰.
- 예전 인터뷰 목록은 이 에이전트·이 run 것. 고르면 대화와 그 기준 시점을 보여 주고, 이어서 질문할 수 있다.
- 리플레이에 쓰는 run 경로는 `?replay=`, 라이브는 `?live=<id>`로 서버가 찾은 run 경로.

## 6. 성공 기준

1. 리플레이를 1일차 16:00에 멈추고 정태우에게 질문하면, 답에 쓰인 기억이 모두 `created_tick <= 그 tick`이다(서버 테스트로 고정). OpenAI 벡터를 가진 run을 Demo 서버로 물어도 실패하지 않는다(차원이 다른 벡터를 곱하지 않음).
2. 같은 에이전트에게 다른 시점으로 물으면 그 시점의 스트레스·기분·기억이 쓰인다.
3. 인터뷰는 `interviews/`에 저장되고, 화면을 닫았다 열어도 예전 인터뷰를 다시 열어 이어서 묻는다.
4. 인터뷰 전후로 run 폴더의 다른 파일 해시가 같다.
5. Demo provider로 API·화면 전체가 동작한다(테스트는 Demo만, 유료 호출 없음).
6. 전체 pytest, ruff, `npm run check` 통과.

## 7. 빌더에게 맡기는 것

- 기억 검색 상위 N, 프롬프트 문구 세부, 대화가 길어질 때 앞부분 자르기 기준.
- 인터뷰 id 형식, 저장 JSON 세부 필드.
- Demo의 규칙 응답 내용(기억 몇 개를 인용하는 정도면 충분).
- 패널 HTML/CSS 세부(목업과 같은 느낌).

## 8. 설계자가 정한 것 (사용자가 확인할 것)

- 엔진 재생 없이 run 파일(기억 DB, inspect, frames, events)로 그 시점을 다시 만든다. 예전 run에서도 되고 빠르다. 대신 엔진 내부의 세세한 상태(진행 중이던 대화의 미처리 메시지 등)는 빠진다.
- 인터뷰 질문에는 비용 확인 창이 없다(호출 수·모델만 표시).
- 열린 인터뷰는 처음 기준 시점을 유지한다. 시점을 바꾸면 새 인터뷰.
- 인터뷰 대화는 에이전트 기억에 들어가지 않는다(run 불변).
- 질문 임베딩은 run 자신의 모델로, 최근성은 retrievals 표로 다시 만든 last_access로, "t까지"는 t 포함.
- run이 나중에 다시 만들어지면 인터뷰에 표시만 하고, 답마다 고른 기억 원문을 저장한다. 기록 재생 중에는 질문을 받지 않는다.
- 채팅 패널은 `#side` 안에서 inspect 자리를 덮는다.
