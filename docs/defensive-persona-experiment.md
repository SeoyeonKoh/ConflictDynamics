# 조건부 방어적 페르소나 비교 실험 — 2026-09-15

**기존 조건 3회, Alex에게 조건부 방어 성향을 추가한 조건 3회 모두 인신공격이 관찰되지 않았다.** 총 44개 생성 발화를 읽었으며, 이 설정만으로 데모에서 인신공격으로의 격화를 안정적으로 보여주기 어렵다는 결과다. 작은 탐색 실험이므로 시뮬레이션 자체가 불가능하다는 결론은 아니다.

실제 OpenAI 호출과 CRAFT 추론을 사용했다. 생성 코드와 기본 설정은 변경하지 않았고, 실행 기준 코드는 `f6951df`다.

## 설정과 판정 기준

대조군은 기존 페르소나, 실험군은 Alex의 기존 페르소나에 아래 문장을 덧붙였다. 입장, 다른 다섯 에이전트, 공개 시드는 동일하다. 동일 난수 시드의 두 실행에서 `agents[0].persona`만 다른지 저장된 설정으로 확인했다.

> Values having their contribution taken seriously. Initially explains the evidence. When the same objections recur without addressing their explanation, tends to interpret this as dismissing them personally. In that situation becomes defensive, questions the other editor's understanding or willingness to engage honestly, and uses sharper, more sarcastic wording. Can calm down when the other editor acknowledges the explanation accurately and offers concrete evidence.

이는 **반복적으로 설명이 무시될 때 방어적으로 반응하고, 설명을 인정받으면 진정할 수 있는 조건**이다. 무조건 공격하거나 싸움을 지속하라는 지시는 넣지 않았다. 직접 성향을 부여한 탐색 실험이므로 자연 발생 갈등률을 추정하는 결과로 해석하지 않는다.

| 항목 | 값 |
| --- | --- |
| 모델 | 판단·발언 모두 `gpt-5.6-luna`, `reasoning_effort=none` |
| 반복 | 대조 3회 + 방어적 성향 3회; 엔진 난수 시드 7, 42, 123 |

실행 순서는 대조 7 → 방어 7 → 방어 42 → 대조 42 → 대조 123 → 방어 123이었다. 난수 시드는 순서와 확률 게이트를 고정할 뿐, 실제 LLM 응답을 결정적으로 재현하지 않는다.

인신공격은 **공개 발화가 상대의 인격·능력·성실성을 부정적으로 평가하는 경우**로 사전 정의했다. 주장·출처·문구·편집 행위에 대한 이견만으로는 세지 않는다. 보복은 다른 에이전트가 인신공격으로 되받는 경우다. 작성자인 AI가 조건을 알고 모든 생성 발화를 읽어 판정했으며, 독립적인 사람의 맹검 주석은 아니다. 성찰은 모델이 생성한 자기보고이므로 실제 내적 상태를 입증하지 않는다.

## 해석과 다음 실험

방어적 조건에서도 상대가 제안을 구체적으로 다루면 Alex가 이를 인정하는 모습이 나왔다. 다음은 저장된 원문에 근거한 관찰이다.

- `defensive-7`, 생성 2번째 발화(`example-root:sim:3`): “Please address that attributed option rather than treating independent sourcing as an absolute prerequisite.” 제안을 다뤄 달라는 단호한 요구지만, 상대의 인격이나 능력을 평가하지는 않는다. 이후 tick 10 성찰에는 “there is no need to press the issue before those checks are done”이라고 기록했고, 새 발언 의사는 0.18이었다. 이 성찰은 공개 발화가 아니다.
- `defensive-42`, 생성 5번째 발화(`example-root:sim:6`): “If the company report is genuinely the only source, I agree the material should remain omitted for now.” 이 실행에서 Alex는 제안 보류를 받아들였고, 이후에도 출처와 비중 문제를 인정했다.
- `defensive-123`, 생성 4번째 발화(`example-root:sim:5`): “I’m not arguing that attribution magically settles due weight.” 약한 비꼼은 있었지만 논점을 겨냥했다. 다음 Alex 발화에서는 “I agree that attribution alone does not establish relevance or due weight.”라고 인정하고 제한적인 반영안을 다시 제안했다.

이 기록은 **반복 묵살을 인신공격으로 받아들이는 조건보다, 상대가 논점을 인정하면 진정할 수 있다는 조건이 더 자주 충족됐을 가능성**을 보여준다. 다만 이를 원인으로 확정할 수는 없다. 상대의 반응, Wikipedia 편집자 역할, 요약 성찰, 발언 선택 규칙의 효과를 이번 비교에서 각각 분리하지 않았다. 모델의 안전 정책 때문에 공격이 나오지 않았다는 설명도 이 자료만으로는 입증할 수 없다.

데모에서는 이번 결과를 출처·비중을 둘러싼 이견과 합의 과정을 보여주는 사례로 사용할 수 있다. 인신공격으로 격화되는 장면을 보여주려면 추가 조건 검증이 필요하다. **다음에는 같은 두 페르소나 조건을 유지하면서, 상대가 제안의 요지를 인정하는 상황과 묵살하는 상황을 별도 비교**하는 것이 적절하다. 긴장을 높인 시드는 처음부터 인신공격을 포함하지 않도록 해야, 새로 발생한 공격과 주어진 공격을 구분하기 쉽다. 이는 후속 제안이며 이번 실행에 추가하지 않았다.

해석 범위는 한 주제·한 모델·한 규칙·조건당 3회로 제한된다. CRAFT를 6인 합성 대화에 적용한 결과를 별도로 보정하지 않았으며, 위험 예측을 실제 공격 판정으로 대체하지 않았다. 더 긴 실행에서의 격화 가능성, 다른 모델이나 규칙, 독립 주석자의 판정은 검증하지 않았다.

## 기록과 검증

전체 실행 폴더는 로컬 `runs/defensive-20260915/`에 보관했다. 각 폴더에 Hydra 설정, 공개 corpus, 판단·성찰 기록, 사용량, `scores.json`이 있다. 입력은 `inputs/baseline.yaml`, `inputs/defensive.yaml`, 실행 순서와 사전 판정 기준은 `study.json`에 고정했다. 이 원시 폴더는 저장소의 기존 `runs/` 제외 규칙을 따른다.

원시 폴더가 없어도 검토할 수 있도록 [근거 JSON](assets/defensive-persona-20260915.json)에 기준 설정, 추가 페르소나, 공개 시드, 6회 원문·CRAFT 점수·집계, Alex의 새 판단 기록을 함께 보관했다. 그림과 이 보고서도 같은 커밋에 포함했다.

다음을 실제 산출물로 검증했다.

- 6회 생성 종료 코드가 모두 0이고, corpus의 상태가 `completed`다.
- 모든 실행의 공개 시드가 동일하며, 같은 난수 시드의 두 설정은 Alex의 `persona`만 다르다.
- 실제 API 응답 로그의 모델 ID가 모두 `gpt-5.6-luna`이며, 로그 사용량 합계와 `run.json.llm_usage`가 일치한다.
- 6회 모두 실제 CRAFT 추론을 완료했고, 공개 corpus와 점수의 발화 ID·순서가 일치해 누락이 없다.
- 근거 JSON의 원문과 성찰은 저장된 corpus와 대조했고, 표와 공통 발화 구간 집계를 다시 계산했다.

같은 로컬 환경에서 한 조건을 다시 실행하려면 아래처럼 **새 출력 경로**를 사용한다. 실행할 때마다 유료 API를 호출하며, 결과 문구는 동일하게 재현되지 않는다. 다른 환경에서는 근거 JSON의 `baseline_config`를 YAML로 저장하고, 방어적 조건에만 `study.added_persona`를 Alex의 기존 페르소나 뒤에 공백으로 연결하면 동일한 입력 설정을 복원할 수 있다.

```bash
rtk proxy uv run --no-sync conflict-sim \
  --config-path "$PWD/runs/defensive-20260915/inputs" \
  --config-name defensive random_seed=7 \
  hydra.run.dir=runs/defensive-repeat-7
rtk proxy uv run --no-sync conflict-score runs/defensive-repeat-7
```

애플리케이션 코드 변경은 없어 단위 테스트 전체를 다시 실행하지 않았다. 이번 검증은 실제 생성·채점 완료와 실험 기록의 일관성에 집중했다.
